Prerequisites

Install the tools, open a terminal, and check out the repository.

Each step below is short. Read it once, then run it.

Quick start

  1. Discover the product.
  2. Capture the requirements.
  3. Plan the work.
  4. Build and verify.

The quick start takes about fifteen minutes on a small project.

Philosophy

The formal requirements baseline lives in Gherkin-style feature files, and every scenario carries a stable requirement ID.

Tests come from requirements, not from the implementation.

A change of meaning gets a new ID rather than an edit.

Branches

Work accumulates on an integration branch and is released from the main line.

The workflow

Three steps: propose a change, apply it, then archive it.

Each step writes a small file next to the code.

Archive

When the change ships, archive it so the specs stay current.
